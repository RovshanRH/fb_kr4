# Учебный репозиторий по практическим работам

## Введение

В этом репозитории собраны несколько практических работ по веб-разработке. Они покрывают разные сценарии: работу с PostgreSQL и MongoDB, клиент-серверное приложение с аутентификацией и ролями, а также демонстрацию балансировки нагрузки через Docker, Nginx и HAProxy.

Каждая практика находится в отдельной папке и может запускаться независимо от остальных.

## Структура проекта

- `package.json` - корневой файл зависимостей и скриптов для части практик.
- `pr19/` - CRUD-приложение на Express + Sequelize + PostgreSQL.
- `pr20/` - CRUD-приложение на Express + Mongoose + MongoDB.
- `pr21/front_4/` - полноценное клиент-серверное приложение магазина с React, JWT, refresh-токенами, RBAC и Redis.
- `pr22/` - демонстрация балансировки нагрузки с несколькими backend-экземплярами, Nginx, HAProxy и Docker Compose.

## Инструкция к запуску

### 1. Установка зависимостей

Для корневых практик установите зависимости из корня репозитория:

```bash
npm install
```

Для практики 21 установите зависимости отдельно в её подпапках:

```bash
cd pr21/front_4
npm install
npm --prefix server install
npm --prefix client install
```

Для практики 22 установите зависимости отдельно в папке `pr22`:

```bash
cd pr22
npm install
```

### 2. Запуск практик

Практика 19:

```bash
npm run server
```

Или напрямую:

```bash
node pr19/server.js
```

Практика 20:

```bash
node pr20/server.js
```

Практика 21:

```bash
cd pr21/front_4
npm run dev
```

Это поднимает backend и frontend одновременно. Адреса по умолчанию:

- frontend: `http://localhost:5173`
- backend: `http://localhost:4001`

Практика 22:

```bash
cd pr22
docker compose up --build
```

После запуска:

- Nginx: `http://localhost:8080/`
- HAProxy: `http://localhost:8081/`

## Описание практик и их выполнение

### Практика 19. CRUD пользователей на PostgreSQL

Сервер на Express использует Sequelize для работы с таблицей пользователей в PostgreSQL. Реализованы операции создания, чтения, обновления и удаления пользователей через REST API.

Что нужно для запуска:

- PostgreSQL на `localhost`;
- база данных `fb_kr4`;
- пользователь `postgres` с паролем `1` либо правки в подключении.

Как проверить выполнение:

1. Запустить сервер из `pr19`.
2. Отправить `POST /api/users` и создать запись.
3. Выполнить `GET /api/users` и `GET /api/users/:id`.
4. Проверить `PATCH /api/users/:id` и `DELETE /api/users/:id`.

### Практика 20. CRUD пользователей на MongoDB

Сервер на Express использует Mongoose и схему пользователя с автоинкрементным `ID`. Поддерживаются те же базовые CRUD-операции, но уже через MongoDB.

Что нужно для запуска:

- MongoDB на локальной машине;
- доступ по строке подключения, заданной в коде.

Как проверить выполнение:

1. Запустить сервер из `pr20`.
2. Создать пользователя через `POST /api/users`.
3. Проверить список через `GET /api/users`.
4. Проверить работу `GET /api/users/:id`, `PATCH /api/users/:id` и `DELETE /api/users/:id`.

### Практика 21. Магазин с аутентификацией, refresh-токенами и ролями

Это клиент-серверное приложение на React и Express. В нём реализованы регистрация, вход, JWT, refresh-токены, защита маршрутов, роли `user`, `seller`, `admin`, а также операции с товарами и управлением пользователями.

Подробное описание практик 7-11 вынесено в отдельный файл: [pr21/front_4/readme.md](pr21/front_4/readme.md).

Что нужно для запуска:

- Node.js и npm;
- Redis на `localhost:6379`;
- зависимости клиентской и серверной частей.

Как проверить выполнение:

1. Запустить проект командой `npm run dev` в `pr21/front_4`.
2. Открыть клиент в браузере.
3. Зарегистрировать пользователя и выполнить вход.
4. Проверить автоматическое обновление токенов при истечении access token.
5. Проверить различия прав для `user`, `seller` и `admin`.

### Практика 22. Балансировка нагрузки

Практика показывает работу нескольких backend-экземпляров за балансировщиками Nginx и HAProxy. В проекте также есть Docker Compose для быстрого поднятия всей схемы.

Что нужно для запуска:

- Docker Desktop или совместимая среда с `docker compose`.

Как проверить выполнение:

1. Запустить стек командой `docker compose up --build` в `pr22`.
2. Открыть Nginx или HAProxy по соответствующим адресам.
3. Отправить несколько запросов на `/` и убедиться, что ответы приходят от разных backend-экземпляров.
4. При необходимости остановить один backend и проверить переключение на резервный экземпляр.

### Практика 23. Балансировка нагрузки — вариант (pr23)

Практика 23 показывает альтернативную настройку балансировщика Nginx с несколькими Node.js backend-экземплярами и поддержкой отказоустойчивости через `max_fails` и `fail_timeout`. В папке `pr23` находятся конфигурация Nginx, `docker-compose.yml`, `Dockerfile` и пример сервера на Express.

Что нужно для запуска:

- Docker Desktop или совместимая среда с `docker compose`.

Как проверить выполнение:

1. Перейдите в папку `pr23`:

```bash
cd pr23
```

2. Соберите и запустите стек:

```bash
docker compose up --build -d
```

3. Отправьте несколько быстрых запросов:

```bash
curl https://localhost/
```

Ответы должны поочерёдно приходить от разных backend-экземпляров (`backend-1`, `backend-2`).

4. Проверка отказоустойчивости:

- Остановите один из backend-контейнеров, например:

```bash
docker compose stop backend2
```

- Повторите `curl`-цикл — Nginx перестанет направлять на остановленный контейнер и продолжит обслуживать трафик через оставшиеся (при наличии резервного `backend-backup` он начнёт принимать трафик, если оба primary упадут).
